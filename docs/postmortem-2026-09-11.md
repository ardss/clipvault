# ClipVault v3 复盘：一个 5 分钟的 bug 如何烧掉 21 小时

日期：2026-09-10 14:57 → 2026-09-11 12:15（跨度约 21 小时，用户本人参与验证 ≥8 次）
损失：用户时间 ×8 轮验证；剪贴板历史被 98 条测试数据 + 30 张孤儿图片污染；用户信任严重受损。

## 最终根因（两个真 bug 叠加一个环境陷阱）

1. **构建方式错误（元凶）**：用裸 `cargo build --release` 打"正式版"。
   Tauri 2 中，不经 tauri CLI 的 cargo build 不会关闭 dev 配置，
   exe 的窗口从 `devUrl (localhost:5173)` 加载界面而不是嵌入产物。
   → vite 进程活着 = 界面正常；vite 死 = 面板全黑/白屏。
   → 正确命令：`npx tauri build --no-bundle`（嵌入 dist）。
   教训：**跨工具链的构建命令不能想当然，CLI 文档读一遍值 21 小时。**

2. **SQL 参数绑定 bug（自己引入）**：修审查发现的 LIKE 注入时，把参数化
   改成了无条件 `query_map([&like])`，但空搜索分支的 SQL 没有 ?1 占位符
   → rusqlite 报 "Wrong number of parameters" → 每次打开面板列表必失败
   → 永远"暂无内容"。前端错误上报（js-errors.log）最终抓到它。

3. **环境噪音**：显示器休眠唤醒导致 WebView2 IPC 单向断流（请求通、响应丢）；
   多次 kill 进程残留 7 个"总在最前"僵尸 WebView 窗口在用户屏幕上，
   用户看到的是死实例残影，我验证的是活实例 → 双方都在说真话却互相对不上。

## 工作流错误（按出现顺序）

| # | 错误 | 代价 | 规矩 |

| 1 | 让用户当测试员：宣称修好→用户验证→碰壁→循环 | 用户 8 轮时间 | 交互类交付前必须自己像素级验证截图 |
| 2 | 后端日志正确 = 交付依据 | 多轮"后端明明好的" | 后端日志只证明后端；UI 要 UI 的证据 |

## 现在生效的防护

- 前端错误自动上报 js-errors.log（这次定位 SQL bug 的关键）
- 面板底部常驻健康条：`N items · ipc Xms`（用户可自检）
- 响应方向心跳看门狗：IPC 断流 10s 自动重载界面
- 启动种子：监听注册前漏掉的首条剪贴板自动补读
- 单实例保护、粘贴 E2E（探针窗口 + 副屏运行）

## 一句话

把"看起来能用"当验收，是一切的地基。验收证据必须来自最终用户看到的同一层。
